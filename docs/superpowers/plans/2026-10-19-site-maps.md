# Site maps (network phase 6, piece C) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give each site a live map of its routers and switches and how they're cabled: found automatically, editable, with traffic every 10 s, sharable, fullscreen and as a dashboard widget.

**Architecture:**
- **Link finding** is a pure Go package (`internal/sitemap`), fed by a database-backed `SiteMapService`. Its inputs are port settings, LLDP neighbours, piece B's MAC placements, and the map's own rows.
- **`LinkPoller`** fast-polls only the ports at link ends, only while a site is watched. It pushes traffic, and edits, through the existing `stream.Hub` to an SSE endpoint.
- **The frontend** works out the tree layout and the link paths in a pure TS model (`utils/siteMap.ts`), then draws devices with the existing realistic drawings, or as cards.

**Tech Stack:** Go (gin, gorm, gosnmp, PostgreSQL/TimescaleDB), React 18 + TypeScript + Tailwind, SSE (`internal/stream`).

**Spec:** `docs/superpowers/specs/2026-10-19-site-maps-design.md`. The approved mockup is `docs/superpowers/specs/assets/2026-10-19-site-maps/site-map-topology.html`: open it in a browser next to its `drawings2.js` and `drawings.css`. It's the reference for layout, link routing and look.

## Global Constraints

- **Map devices:**
  - The site's devices with an effective type of `router` or `switch` (`COALESCE(device_type, device_type_detected)`), plus devices an editor added.
  - Nothing else ever appears: no APs, NVRs, UPSes or other devices.
- **Link sources:**
  - In order of trust: hand-drawn, port setting (`device_interfaces.neighbor_device_id`/`neighbor_if_index`), LLDP (`l2.neighbors`), and MAC guess (piece B placement).
  - One link per port pair. A guess is never drawn for a device that LLDP or a port setting already links.
- **LLDP port matching, in this order:**
  1. the port ID or description equals `ifName`, `ifDescr` or `ifAlias`
  2. "Port N" is the port whose faceplate label is N
  3. the port ID is a MAC held by exactly one physical port (`portmon.IsPhysical`)
  4. the device itself, with no port
- **Stale links:** an LLDP link or guess not seen for 24 h is drawn faded with "not seen since …", and dropped after 7 days. Hand-drawn links and port settings never go stale.
- **Colour:** by the busier direction's utilisation `u` against the rate port's busy threshold `t`, which is the port's `util_threshold_pct`, else the instance default (80).
  - `u < 1`: slate
  - `u < t/2`: green
  - `u < t`: amber
  - otherwise: red
- **Width:** 100 Mb → 2, 1 Gb → 3, 2.5 Gb → 4, 10 Gb → 5, 25 Gb and above → 7 (map units). An unknown speed draws at width 3, dashed for 14 units at each end.
- **Problems:** a port that's down draws red with no flow. A device that's down greys its links and dashes them. A link with no sample for 30 s turns grey with "no data".
- **Fast poll:**
  - Every **10 s** while watched, **≤ 64 ports per device**, one fast poll per device at a time.
  - Only devices that are `enabled`, `status = 'up'` and have `consecutive_failures = 0`.
  - Stops **60 s** after the last viewer goes. A widget or public request counts as watching for 60 s.
- **Editing:** admins and editable sharers (`SiteAccessEditable`).
  - Changes save as they're made.
  - Positions snap to an **8-unit** grid.
  - Phones are view-only.
- **Public link:**
  - Admin-only, and needs its creator still to be an admin, as with dashboards.
  - It leaves out host or IP addresses, MACs, serial numbers, status details and endpoint counts. Ports go through `dashboards`' `trimPort` rules.
- **Copy, exact:**
  - "Live"
  - "Updated N s ago" / "Updated N min ago"
  - "Reconnecting…"
  - "Not linked"
  - "▾ N below"
  - "N switches folded · M down"
  - "not seen since …"
  - "no data"
  - "Down N min"
  - Tooltip: "QuantumLink port 51 ↔ Quantum-Gate eth10 · ↓ 412 Mb/s ↑ 38 Mb/s · 1 Gb"
- **Migrations:** the new file is `backend/migrations/064_site_maps.sql`, with TIMESTAMPTZ only. Never edit an applied migration. The tables are in `public` so they're backed up.
- **Gates:**
  - **Backend:** `cd backend && go vet ./... && go test ./...`, plus `./scripts/test-db.sh -run <Name> -v` for database tests. There's no race detector here (no gcc).
  - **Frontend:** `docker run --rm --user $(id -u):$(id -g) -e HOME=/tmp -v "$PWD/frontend":/app -w /app node:20-alpine sh -c "npm ci --no-audit --no-fund --silent && npx tsc --noEmit && npx eslint src --quiet && npx vite build --logLevel error"`
  - **Pure TS:** a throwaway esbuild check script in the scratchpad (`$S/smcheck/check.ts`), run as the previous plans do. `utils/siteMap.ts` may import only types from `@/`.
- **Design system:** slate, with the 8 accents in `utils/colors.ts`. Never put `*/` inside a CSS comment.

## Rulings already made in this plan

These are where the spec left a choice. Each says what it costs if wrong.

- **R1. Realistic drawings** show on the map page, in fullscreen and on the public map, which gets a trimmed ports endpoint. The site page card and the dashboard widget draw **Simple** only: a widget refresh carrying 20 devices' ports every 10 s is too heavy. *Cost if wrong:* adding realistic to the widget later.
- **R2. The frontend owns the automatic layout,** because it knows drawing sizes. The backend stores only saved positions. Layout slots are sized per tier, the same in both views. *Cost if wrong:* moving one pure function.
- **R3. The fast poll reuses `snmp.ReadStats`** (10 OIDs per port) plus one `sysUpTime` GET, rather than a narrower OID set. *Cost if wrong:* slightly bigger SNMP responses.
- **R4. `site_map_positions.added`** marks a device of another type that an editor put on the map. *Cost if wrong:* one column.
- **R5. The fast poll** has its own semaphore of 4 devices at once, like `L2Monitor`. *Cost if wrong:* a constant.
- **R6. When the stream sends what:**
  - The `map` event, the whole topology, goes on connect, after every edit, and every 5 minutes, which matches the L2 poll.
  - The `traffic` event goes every 10 s.
  - *Cost if wrong:* the timer values.
- **R7. Per-browser keys:**
  - The view choice: `sentinel:map-view` (`realistic` or `simple`, default `realistic`).
  - Folds: `sentinel:map-folds` (JSON of site id → device ids).
  - *Cost if wrong:* the key names.
- **R8. A map with no router** starts its tree from the switch with the most links, ties by name. *Cost if wrong:* the root rule.
- **R10. The public map's link panel** has no last-hour sparkline, because public viewers have no metrics access. *Cost if wrong:* a trimmed public metrics route.
- **R9. The site page card** sits above the right column's tab bar, Simple, 260 px tall, with "Open map →". *Cost if wrong:* a few styling lines.

## Review Focus

1. **A device deleted, moved to another site, or changed to an AP while a map is open.** The next `map` event drops it and its links, with no 500s and no orphan positions. *Test in Task 4.*
2. **Two cables between the same two switches** (a LAG or a redundant pair) stay two links. Links are merged only on the same port pair. *Test in Task 2.*
3. **A device-level LLDP link and a port-level link between the same two devices** merge into the port-level one, rather than drawing two. *Test in Task 2.*
4. **Revoking a public link, or a viewer losing site access, while a stream is open** ends that stream within one traffic tick. *Test in Task 6.*
5. **A device whose 64-bit counter support isn't known yet** isn't fast-polled until the regular poll learns it. A device without 64-bit counters is fast-polled on 32-bit counters. *Test in Task 5.*

**How `Snapshot` is built:**
- It gathers `sitemap.Input` from the site's devices, their `device_interfaces`, the port links, `l2.neighbors` rows on map devices, `Placements` of the map devices' physical-port MACs, and the site's `site_map_links`. Then it calls `sitemap.Find`.
- **A guess** comes from a placement with `How` of "wired" or "behind" on a port of another map device.
- **Each end's `Label`** comes from `portmon.NumberingFor(sysDescr).Label`, and its `Name` is the `ifName`.
- **`RateEnd`:** the end that has a port, preferring a switch over a router, then a known speed. `SpeedBps` and `ThresholdPct` are that port's (`util_threshold_pct`, else `settings.PortThresholds(ctx).UtilPct`).
- **`DownSince`:** `last_seen_at` while the status is down.
- **`Connected`:** the end-device count from `EndpointService.ForDevice(...).Endpoints` plus clients. It's computed only when not public, and is nil on public snapshots.
- **`PublicSnapshot`:** `Host`, `StatusDetail` and `Connected` are empty, and `CanEdit` is false.
