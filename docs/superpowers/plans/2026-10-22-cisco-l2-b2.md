# Cisco L2 (B2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cisco switches report every VLAN's MAC table, CDP neighbours match and classify correctly, and Cisco Port-channels work as LAGs, as the read-only walk of 2026-10-21 showed is needed.

**Architecture:** The five-minute L2 poll (`services/l2_monitor.go`) gains per-VLAN dot1d walks through a VLAN context on the SNMP target, CDP capabilities and per-address keys, and a broader aggregator test. Matching (`sitemap.MatchNeighborDevice`, placement's `world.monitored`) gains a domain-free name step; placement (`l2.ClassifyPort`, `world.place`) learns two new port facts. No migration: `l2.sightings.vlan`, `l2.neighbors.caps` and `device_interfaces.lag_if_index` exist.

**Tech Stack:** Go 1.26, gosnmp v1.45.0, GORM, PostgreSQL 16 + TimescaleDB.

**Spec:** `docs/superpowers/specs/2026-10-22-cisco-l2-b2-design.md`

## Global Constraints

- Test first: write the failing test, run it and see it fail, then make it pass.
- No work data in the repo: fixtures use made-up MACs, addresses and names (`10.x` test addresses, `corp.example` domains) in the shapes the walk showed.
- Match the surrounding code's style and comment density; plain-language commit messages; `git add` with explicit paths only.
- Unit tests: `cd backend && go test ./internal/<pkg>/ -run '<Name>' -v`. DB tests: `cd backend && ./scripts/test-db.sh -run '<Name>' -v`. (On the work host, which has no Go, both run through the golang:1.26 wrapper.)
- `portmon.IsLAG` and `DefaultCollect` are not changed.
- Never edit an applied migration; this plan needs none.

## Review Focus

1. Every VLAN context read fails (a community or v3 user without VLAN-context access): the poll must still read the default context, so VLAN 1's MACs keep refreshing. Test in Task 3.
2. A switch whose Q-BRIDGE has rows (UniFi, EdgeSwitch) must never walk the VLAN table: no extra walks, nothing changes for them. Test in Task 3.
3. A CDP device ID that is an IP address ("10.99.1.1") keeps its whole name; today it is cut to "10". Test in Task 4.
4. The domain-free name step never matches the reporting device itself, and "exactly one" counts only the other devices (the C3850's sysName is `Switch.<domain>`, and an unconfigured Cisco next to it sends `Switch`). Test in Task 6.
5. A LAG member that is a link only because a person set its role (no neighbour) still makes its aggregator a link. Test in Task 7.

### Task 3: Per-VLAN sightings in the L2 poll

**Interfaces:**
- Consumes: `snmp.Target.InVLAN`, `Target.Context` (Task 1); `l2.ParseVLANs`, `l2.OIDVtpVlanState`, `l2.OIDVtpVlanType` (Task 2).
- Produces: nothing new outside the file.

`fakeL2SNMP` gains `contexts map[string]map[string][]snmp.PDU` and `ctxErrs map[string]map[string]error`, keyed by the walk's context: `t.Context` when set, else `t.Credential.Community`. A walk whose context key is in `contexts` answers from there (and `ctxErrs`); otherwise from `rows`/`errs` as today. It also records every walk as `walked []string` of `"<context> <root>"`.

Flow (spec §1): Q-BRIDGE rows → as today. Q-BRIDGE answered empty → walk `OIDVtpVlanState` and `OIDVtpVlanType`; `ParseVLANs` non-empty → per VLAN, on `t.InVLAN(v)`, walk dot1d port, status and base; entries get `VLAN = v`; bridge ports map through that VLAN's base table, else the default-context `base`, else `ifIndexes` (extend `bridgeToIfIndex` or call it twice). A VLAN whose port walk fails is skipped. If no VLAN's port walk succeeded, or there are no VLANs, read the default context's dot1d as today.
